# Trend Rader · 트렌드레이더

[트렌드레이더 열기](https://trendrader.vercel.app/)

뉴스·영상·블로그·GitHub·커뮤니티의 공개 정보를 검색하고, 수집 결과를 CSV로 저장해 Grok에서 분석하는 서비스입니다. PC와 모바일에서 사용할 수 있습니다.

## 주요 기능

- **정보검색:** 검색어와 출처·분야·언어·기간·정렬 조건으로 정보를 수집합니다. 뉴스·YouTube·커뮤니티·블로그·GitHub 결과를 탭별로 확인하고 원문으로 이동할 수 있습니다.
- **인기검색어:** Google Trends 검색어를 누르면 바로 검색합니다. 모바일에서도 검색창 팝업 없이 결과를 확인합니다. Trends 연결 실패 시 사이트 내 검색 기록 등 표시된 출처 범위를 확인하세요.
- **검색조건 기억:** 마지막 검색어와 검색조건을 브라우저에 저장해 재실행 후에도 이어서 사용합니다. 브라우저 데이터를 삭제하거나 다른 브라우저·기기를 사용하면 저장된 조건이 공유되지 않습니다.
- **영상검색:** 조회수와 채널 규모를 비교하며 관심 영상을 탐색합니다.
- **커뮤니티:** 국내·해외 범위와 국가, 정렬 조건을 선택해 커뮤니티 게시물을 검색합니다.
- **수집정보 분석:** 화면의 검색 결과를 CSV로 내려받고, 연결된 xAI Grok 프로젝트에서 직접 업로드해 분석합니다.
- **피드:** 닉네임과 비밀번호로 글·댓글을 등록하고 수정·삭제합니다. 관리자 공지는 상단에 고정됩니다.
- **수집 상태:** 출처별 연결 성공·실패와 조회·표시 건수를 확인합니다. 갱신 실패로 이전 결과를 보여줄 때는 안내와 수집 시각을 표시합니다.

## 검색 사용법

1. **정보검색**에서 출처·분야·언어·기간·정렬을 선택합니다.
2. 검색어를 입력한 뒤 검색 버튼을 누릅니다. 인기검색어를 누르면 해당 검색어로 즉시 검색합니다.
3. 결과 탭으로 출처를 좁히고 **원문 보기**로 내용을 확인합니다.
4. 필요한 경우 **현재 결과 CSV 저장**을 눌러 현재 표시된 결과를 저장합니다.

처음 접속할 때 정보검색 기본 조건은 전체 기간·최신정보 순입니다. 자동 갱신을 켜면 1분 간격으로 갱신하며, 숨겨진 탭에서는 갱신을 중지합니다.

검색 결과는 공개 RSS·API·검색 페이지에서 제공되는 범위입니다. 전체 게시물이나 초 단위 실시간 순위를 의미하지 않습니다. 인기순은 출처별 조회·반응 등 제공 지표를 사용하므로 서로 다른 플랫폼의 수치를 같은 단위로 해석하지 마세요. 기간 필터에서는 게시 시각이 없는 자료가 제외될 수 있습니다.

## Grok으로 수집정보 분석하기

1. 원하는 검색을 실행한 뒤 **현재 결과 CSV 저장**을 누릅니다.
2. **수집정보 분석**을 누르면 [Grok 공유 프로젝트](https://grok.com/project/00d49a5c-655b-47d7-b477-9a07ec8e901b?tab=conversations)가 새 창에서 열립니다. 버튼에 마우스를 올리면 사용설명을 확인할 수 있습니다.
3. 열린 Grok 화면에서 **자신의 계정으로 로그인**합니다.
4. 다운로드한 CSV 파일을 직접 업로드한 뒤 분석을 요청합니다.

예: “이 기사 목록의 핵심 이슈를 묶고, 반복 등장하는 주제와 콘텐츠 제작 기회를 정리해 줘. 근거가 되는 기사 제목과 URL도 함께 제시해 줘.”

이 버튼은 Grok 프로젝트를 여는 연결 기능입니다. CSV 자동 전송이나 xAI API 자동 분석은 수행하지 않습니다. 프로젝트 접근과 파일 업로드 가능 여부는 로그인 계정의 권한 및 Grok 서비스 상태에 따릅니다.

## 피드 작성과 닉네임

- 글은 제목·본문·닉네임·비밀번호를, 댓글은 본문·닉네임·비밀번호를 입력해 등록합니다.
- 기존 글 또는 댓글에 등록된 닉네임을 사용하려면 해당 닉네임의 비밀번호가 일치해야 합니다. 다르면 등록되지 않으며 비밀번호를 확인하거나 다른 닉네임을 사용하라는 안내가 표시됩니다.
- 수정·삭제할 때도 작성한 닉네임과 비밀번호를 입력합니다. 비밀번호는 기억해 두세요.
- 관리자 비밀번호로 작성한 글은 공지가 됩니다. 목록은 페이지당 최대 50개를 표시합니다.
- 비밀번호 검증 정보가 없는 예전 댓글은 관리자만 수정·삭제할 수 있습니다.

글과 댓글은 GitHub 저장소에 보관합니다. 공개 저장소를 사용하면 본문과 닉네임이 공개되며, 삭제 전 내용도 Git 이력에 남을 수 있습니다.

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```powershell
npm.cmd ci
Copy-Item .env.example .env
npm.cmd start
```

서버 PC에서는 [localhost:3000](http://localhost:3000)으로 접속합니다. 같은 Wi-Fi/LAN의 모바일이나 다른 PC에서는 서버 로그의 **같은 네트워크 접속** 주소를 사용합니다. Windows 방화벽 안내가 나오면 Node.js의 사설 네트워크 접근을 허용하세요. 종료는 `Ctrl+C`입니다. HTML 더블클릭이나 Live Server만으로는 검색 API가 작동하지 않습니다.

기본 `HOST=0.0.0.0`, `PORT=3000`은 `.env`에서 변경할 수 있습니다.

## 운영 설정

실제 키와 토큰은 `.env` 또는 호스팅 환경변수에만 입력하고 저장소에 커밋하지 마세요.

- **검색:** `YOUTUBE_API_KEY`, `GITHUB_TOKEN`은 선택 사항입니다. YouTube 키가 없으면 공개 검색 HTML을 사용합니다. 공개 RSS·HTML은 구조 변경이나 접근 제한으로 실패할 수 있습니다.
- **Reddit:** 승인받은 `REDDIT_ACCESS_TOKEN`과 실제 앱·연락 정보를 담은 `REDDIT_USER_AGENT`를 사용할 수 있습니다. 토큰 발급·자동 갱신은 포함하지 않습니다.
- **피드:** `BOARD_GITHUB_TOKEN`에 해당 저장소의 Contents 읽기·쓰기 권한을 부여하고, `BOARD_PASSWORD_PEPPER`에 32자 이상의 무작위 서버 전용 값을 설정합니다. `BOARD_ADMIN_PASSWORD`로 관리자 기능을 설정합니다. 저장 대상은 `BOARD_GITHUB_REPOSITORY`, `BOARD_GITHUB_BRANCH`로 지정합니다. 보호 키는 기존 글 인증에 필요하므로 보관하고 임의로 변경하지 마세요.
- **방문자 집계:** Upstash Redis의 `KV_REST_API_URL`/`KV_REST_API_TOKEN`, `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` 또는 `VISITOR_REDIS_REST_URL`/`VISITOR_REDIS_REST_TOKEN`을 설정합니다. 현재 접속은 최근 90초 활성 브라우저, 누적 방문은 집계 도입 후 기록된 고유 브라우저 기준입니다.

피드 저장소 설정이 없으면 작성 기능을 사용할 수 없습니다. 비밀번호는 서버 보호 키와 salted scrypt로 검증하고 공개 API 응답에서는 검증값을 제외합니다.

## 검증과 배포

```powershell
npm.cmd test
```

자동 테스트는 모의 응답으로 검색·화면·CSV·피드 등 주요 동작을 검증합니다. 실제 외부 수집 상태는 `node probe.mjs`로 별도 점검할 수 있습니다.

Vercel 프로젝트가 연결된 환경에서는 다음 명령으로 배포합니다. 운영 환경변수도 Vercel에 설정해야 합니다.

```powershell
npx vercel --prod --yes
```

화면 소스는 `public/`, 서버는 `server.js`, 피드 저장 처리는 `board.js`에 있습니다. `/api/health`는 서버 생존 상태를 확인하며 외부 출처의 정상 동작까지 보장하지 않습니다. 현재 구성에는 검색 수집 이력의 영구 저장, 회원·결제·알림·백그라운드 상시 수집이 포함되지 않습니다.
